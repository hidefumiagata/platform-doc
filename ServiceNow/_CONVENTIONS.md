# ServiceNow ナレッジ 執筆規約

本ナレッジは、ITコンサルタント・アーキテクト・エンジニアが読み、かつ AI が読み込んで質問に回答するための Markdown ドキュメント群である。全ファイルは本規約に従う。

## 1. 基準リリース

- **基準リリース：Australia**（2026-05-05 GA。年2回リリースのうち、本ナレッジ作成時点 2026-11-02 で GA が確定している最新ファミリー）。
- 次期ファミリー **Brazil**（2026-09 EA、GA 日付は情報源により 2026-10〜11 で不一致）で変更・追加・廃止が判明しているものは、本文中に「> **Brazil での変更:** …」の形で併記する。
- 旧リリース（Zurich、Yokohama、Xanadu 等）で導入された機能は、導入リリースが判明していれば「（Xanadu で導入）」のように記載する。
- リリース名の時系列：… Utah → Vancouver → Washington DC → Xanadu → Yokohama → Zurich → Australia → Brazil。

## 2. ファイル構成

```
ServiceNow/
  README.md            … 全体目次（AI が最初に読む入口）
  _CONVENTIONS.md      … 本規約
  glossary.md          … 用語集
  01_入門編/
  02_リファレンス/<領域>/
  03_導入編/
  04_応用編/
  assets/images/<ファイルのslug>/  … 画像
```

- 1ファイル1トピック。目安は 300〜1,500 行。超える場合は分割せず、見出しを細かく切る。
- ファイル名は英小文字のケバブケース（例：`incident-management.md`）。

## 3. フロントマター（必須）

各ファイルの先頭に以下を記載する。

```yaml
---
title: Incident Management（インシデント管理）
category: introduction | reference | implementation | advanced
domain: platform | itsm | itom | itam | spm | secops | irm | employee | customer | industry | ai | general
release: Australia
last_verified: 2026-11-02
summary: 1〜2文でこのファイルが何に答えるかを書く（AI の検索用）
keywords: [incident, インシデント, ITSM, ...]
sources:
  - https://www.servicenow.com/docs/...
---
```

## 4. 本文の書き方

- 本文は日本語。製品用語・画面項目・テーブル名・ロール名は**英語正式名称を主とし、初出時に日本語訳を併記**する（例：`Assignment group（割り当てグループ）`）。
- テーブル名・ロール名・プロパティ名・API 名はバッククォートで囲む（例：`incident`、`itil`、`glide.ui.session_timeout`）。
- 冒頭に「## 概要」、末尾に「## 参照元」を必ず置く。
- AI が単独のチャンクでも理解できるよう、各見出しの直下で主語を省略しない（「このテーブルは」ではなく「`incident` テーブルは」）。
- 表を積極的に使う（フィールド一覧、ロール一覧、状態遷移、比較）。
- 状態遷移・アーキテクチャは Mermaid 図で表現してよい。

## 5. 出典と情報の確度（全編必須）

- すべての事実記述は出典をたどれるようにする。節ごと、または文末に `[出典](URL)` を付け、末尾「## 参照元」に URL 一覧をまとめる。
- 情報源の優先順位：①ServiceNow 公式ドキュメント（servicenow.com/docs, docs.servicenow.com）②公式サイト・公式ブログ・リリースノート・ServiceNow Community の公式記事 ③Developer サイト（developer.servicenow.com）④パートナー・第三者ブログ・調査会社 ⑤フォーラム投稿。
- 確度ラベルを付ける：公式情報以外に依拠する記述には以下を付ける。
  - `【第三者情報】` … パートナー・第三者の公開情報に基づく
  - `【推定】` … 複数情報からの推定、価格の推定値など
  - `【経験則】` … 一般に語られる実務上の知見
- 確認できなかった事項は推測で埋めず、「公開情報では確認できず」と書く。
- **価格**は公式に定価が公開されていない。価格を書く場合は必ず「推定値・出典・取得日」をセットにし、`【推定】` を付ける。

## 6. 画像

- 画面スクリーンショット等の画像は、公式ドキュメント等から取得して `assets/images/<slug>/` に保存し、相対パスで参照する。
- 画像の直下に必ず以下を書く（AI は画像を読めない前提で、文章だけで画面が分かるようにする）。
  - キャプション（何の画面か）
  - 画面の文章による説明（メニュー位置、主要項目）
  - 出典 URL と取得日
- 画像の著作権は ServiceNow, Inc. 等の権利者に帰属する。本リポジトリは社内の参照目的に限り、外部への再配布はしない。
- 取得できなかった場合は無理に入れず、公式ページへのリンクと文章による画面説明で代替する。

## 7. 編ごとの役割

| 編 | 目的 | 読者 |
|---|---|---|
| 01_入門編 | ServiceNow を語るうえで必須の基本事項 | 入門者が最初に読む |
| 02_リファレンス | 製品仕様の詳細（テーブル、ロール、設定、API、画面） | AI 回答の主たる根拠、エンジニア・アーキテクト |
| 03_導入編 | ライセンス・価格・エディション、導入方法論、運用 | コンサルタント・PM |
| 04_応用編 | 導入・運用経験者の知見（失敗パターン、ベストプラクティス） | 経験者・コンサルタント。**出典 URL 必須** |
